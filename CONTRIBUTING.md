# Порядок изменений

Ветка на одно изменение → issue с JR-ID → небольшой PR → проверка на копии CRM → обновление docs/ADR → локальный rollout с backup. Начальный remote рекомендован private до проверки экспорта и истории на секреты. Публичную лицензию выбрать отдельно.

Сначала зафиксировать as-is; новые функции запрещены до Baseline gate. Для изменения контракта указать старые/новые поля, миграцию существующих строк и rollback. Runtime workflow — источник поведения до снятия baseline; Git станет источником версий после подтверждённого export/import.

PR включает проблему, итоговое поведение, validation evidence, влияние на first_seen/last_seen и CRM, rollback. Не делать mass reformat JS одновременно с extraction. Не добавлять фейковые workflow и passing tests вместо отсутствующих материалов.
