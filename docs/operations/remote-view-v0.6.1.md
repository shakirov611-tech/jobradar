# Подтверждённый remote в основной выдаче — v0.6.1

Решение пользователя 2026-10-29: вакансии с одной локацией без remote скрываются из
основного списка, но сохраняются для проверки. Перед решением учитываем и описание.

После обновления файлов в прежней папке (сохранить .env.integration и .collector-state):

```powershell
npm.cmd run collector:preview -- --open
```

Основной список обзора теперь открывается по умолчанию:
- подтверждён remote (включая явное home-based/WFH) в location/workplace либо узнаваемой формулировке описания;
- не обнаружено явного ограничения страны, исключающего BG;
- прошёл прежний фильтр ролей. Это не подтверждение персонального соответствия.

«Формат неясен»: только город/страна, нет достаточного remote evidence, либо
противоречивые условия. «Исключено условиями»: office/onsite, mandatory hybrid,
явный запрет remote или обнаруженное ограничение страны. «Все группы» возвращает
полную выдачу. Ролевой фильтр и просмотр всех полученных вакансий остаются доступны.

Рядом с форматом есть причина и короткий фрагмент evidence. Источник подтверждения
и country evidence сохраняются в JSON. Описания анализируются до усечения для CRM,
включая Lever lists/additional и Greenhouse entity-encoded HTML; лимит анализа 120000
символов. HTML не выполняется, snippets экранируются в обзоре.

Общие упоминания remote клиентов/инструментов не подтверждают условия этой роли.
Структурный hybrid или явная обязательная работа в офисе исключают из основной выдачи.
Remote и одновременный запрет remote дают unclear. Местонахождение офисов компании
не считается ограничением страны. Явные must-be-based/country-only ограничения для
известных стран проверяются отдельно; BG как альтернатива в том же предложении
не отклоняется. Europe/EMEA/unknown остаются предварительной географией, не доказанным
правом на найм. Main может содержать remote с неизвестной country eligibility.

Граница изменения: фильтруется основной HTML список, не историческая CRM. Старые строки
Google Sheets не удаляются; scheduled writer продолжает обновлять ролевых кандидатов,
включая unclear/excluded. Это сохраняет last_seen и ручные статусы. Метрика matched
по-прежнему означает role candidates; views.main/unclear/excluded — отдельные счётчики.
Нет новых столбцов, ключей, миграции или переустановки Windows task для этой версии.

Это детерминированные языковые эвристики, не полное понимание текста. Неизвестные
формулировки и страны могут остаться review; возможны ошибки. Seniority, домен,
язык команды и разрешение на работу пока не подтверждаются. Оценивать точность
нужно по реальной разметке, не только по количеству скрытых строк.
