# Проверки одной командой — первый runner

Статус: runner и генератор реализованы; изолированные проверки и mocked HTTP lifecycle проходят. Проверка с настоящим n8n/Sheets ещё не выполнена. Совместимость Public API activation и Webhook node проверяется первым локальным запуском для установленной версии n8n. Никакие production workflows не импортируются и не обновляются runner-ом.

## Разовая настройка (Windows или WSL)

1. Получить актуальную ветку проекта. Установить Node.js 22+; Docker/n8n остаются как есть.
2. В отдельной тестовой копии Google spreadsheet создать **пустой** лист `JR_TEST_Vacancies`, скопировать только строку заголовков из Vacancies. Нужны все поля нормализатора и `first_seen_at`, `notes`, `review_status`. Не копировать рабочие строки. Credential n8n должен иметь доступ к этой копии.
3. Скопировать `.env.integration.example` в `.env.integration`. Указать localhost URL, локальный n8n Public API key, ID существующего Google credential (не OAuth token), ID рабочей таблицы для защиты от совпадения, ID тестовой таблицы и имя листа. Поля не отправлять в чат и не коммитить. ID credential доступен в локальном экспорте исходного workflow; ключ Public API создаётся в n8n, если доступен для вашей установки. Не использовать MCP URL вместо API origin.
4. Снять версию: `docker exec jobradar-n8n n8n --version`. Запускать runner в том же окружении, откуда localhost:5678 доступен; обычно Node на Windows вместе с браузером либо WSL с доступом к порту.

## Каждый следующий запуск

```bash
npm test
npm run test:integration
```

Не нужно npm install: внешних зависимостей пока нет. Ключ и таблица загружаются из локального env-файла. Первый запуск требует доступных Public API create/activate/deactivate/delete workflow и прав на использование Google credential в проекте. Если API возвращает 401/403 или несовместимый 4xx, runner завершится ошибкой, без попытки переключить production workflow. В этом случае достаточно предоставить версию и код ошибки, без секретов.

## Что происходит

Runner разрешает только HTTP loopback, запрещает совпадение production/test spreadsheet и требует test tab prefix. Генерирует случайный run ID и путь webhook; создаёт отдельный workflow через API и активирует его на время теста. Этот workflow читает тестовый лист, отказывается писать при обнаружении нетестовых строк с vacancy_id, нормализует синтетическую вакансию исходным JS и делает append/update. Первый проход задаёт контрольные ручные поля; второй обновляет машинное поле и last_seen. Последнее чтение проверяет одну запись, изменения и сохранность ручных значений.

Проверка first_seen относится к сохранению уже существующего значения, **не к его созданию действующим сборщиком**. Timestamp не подменяется в исходнике. Ошибки envelope/ID проверяются в `npm test`; это пока не end-to-end проверка ошибочного запуска n8n.

При завершении временный workflow деактивируется и удаляется. Отчёт сохраняется в `.test-artifacts/<runId>.json` (Git игнорирует). Синтетические строки в выделенном test листе пока остаются: это не полная очистка Google ресурсов. Следующий прогон использует новый ID и проверяет только свои строки. Runner не очищает таблицы и не удаляет строки. Позже добавим отдельный управляемый cleanup/создание временных листов после локального подтверждения API.

Ошибка webhook или timeout не повторяется автоматически. Неоднозначный сетевой сбой при создании workflow может оставить ресурс; при cleanup failure отчёт указывает известный workflow ID. Случай Ctrl+C/остановки компьютера также требует проверки временных workflow `JR TEST ...` в локальном n8n. Деактивация/удаление не обещает остановить уже исполняющуюся запись при timeout; до ручного повторного запуска проверить локальное исполнение.

Prefix/проверка ID — защита от случайного выбора, а не независимое доказательство правильной настройки: production ID нужно указать честно. Backup/restore и рабочую CRM этот runner не подменяет. Не открывайте localhost в интернет.

## Исходник и workflow

После изменения `src/normalization/greenhouse-airbnb.n8n.js` выполнить `npm run workflow:build`. `npm test` падает, если JSON импорта содержит другой jsCode. Исторический baseline workflow не пересобирается.

## Проверки runner-а

Unit tests проверяют конфигурацию, только test resources, синтаксис generated Code nodes и отсутствие сетевого Greenhouse fetch. Mock transport tests проверяют create/activate/call/cleanup и отсутствие retry при ошибке webhook. Они не подтверждают API schema или Google node runtime: эти границы остаются за реальным локальным integration run.

## Исправление регистрации и cleanup (n8n 2.45.5)

Первый локальный запуск вернул webhook 404 и DELETE 409. URL совпал с UI; runtime 2.45.5. Асинхронная публикация/снятие публикации — рабочая гипотеза, не доказанная причина из двух HTTP-кодов. Runner теперь сохраняет ограниченный message ответа с удалением известных секретных значений.

До 10 секунд ожидает регистрацию только если n8n явно отвечает code=404 и message содержит requested webhook, not registered и точный путь этого run. Другие 404, 5xx, timeout и lost connection не повторяются. После deactivate повторяет DELETE при 409 до 10 секунд только для созданного им workflow; 404 удаления трактуется как уже удалённый ресурс. Проверено mock-сценариями задержанной регистрации/удаления. Фактическая совместимость требует повторного локального прогона.

Старый оставшийся JR TEST workflow автоматически не удаляется новым запуском. Его можно отдельно архивировать/удалить в UI после проверки, что это синтетический workflow прежнего запуска и он не исполняется. Production workflow не затрагивать.
