# Автоматическая настройка collector v0.4

После обновления файлов проекта выполните из его корня:

```powershell
npm.cmd run collector:setup
```

Нужен существующий `.env.integration`. Команда использует N8N_BASE_URL,
N8N_API_KEY, N8N_GOOGLE_CREDENTIAL_ID и JR_PRODUCTION_SPREADSHEET_ID.
Тестовые параметры также проходят существующую проверку раздельных окружений.
Рабочий лист — Vacancies; при необходимости задайте JR_PRODUCTION_SHEET_NAME.

Скрипт создаёт отдельный `JobRadar — Vacancy Collector v0.4 [managed]`,
настраивает оба Sheets-узла и печатает ссылку. Откройте её и нажмите Execute.
Повторите Execute после завершения первого запуска для проверки дедупликации.
Не запускайте старый и новый collector одновременно.

Скрипт не выполняет сбор, не публикует workflow и не изменяет старый collector.
Повторная команда проверяет и возвращает существующий managed workflow.
При расхождении конфигурации, изменении узлов или нескольких копиях выполнение
останавливается. Не переименовывайте managed workflow: имя служит идентификатором.
После таймаута создания сначала проверьте наличие workflow в n8n; POST не повторяется
автоматически. Параллельные запуски setup не поддерживаются.

Тесты скрипта используют подставной API. Создание через реальный n8n API проверялось
интеграционным runner; именно production setup ещё требует локальной проверки.
