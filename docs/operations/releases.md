# Порядок выпуска JobRadar

1. Определить изменения и поднять version в package.json. Для 0.x: minor — новая возможность, patch — совместимое исправление/уточнение; breaking changes явно описывать.
2. Обновить README, инструкции, архитектуру/модель данных и ADR, если изменилось решение. Добавить запись в CHANGELOG.md и notes в docs/releases/.
3. Выполнить необходимые тесты; проверить CI на точном commit PR. Отдельно указать, выполнен ли локальный n8n integration test.
4. Объединить PR. Выбрать конкретный commit для тега; проверить соответствие версии package.json и notes.
5. Создать тег vX.Y.Z и GitHub Release с подготовленными notes. Не переносить опубликованный тег на другой commit. Ошибку исправлять новой версией.
6. Проверить опубликованную страницу, тег и архив исходников. Сообщить пользователю ссылку и команду обновления.

Release не является автоматическим развёртыванием в Windows/n8n. Пользователь обновляет файлы локально;
.env.integration и .collector-state сохраняются. Не публиковать секреты или локальные отчёты.
Если публикация заблокирована, явно сообщить «подготовлен, не опубликован».
