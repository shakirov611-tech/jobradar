# JobRadar — Product Backlog

Это список следующих результатов и критериев приёмки. Текущая готовность и доказательства ведутся только в [roadmap](roadmap.md); scope этапов — в [плане](implementation-plan-v1.md).

| Задача | Порядок / зависимость | Следующий результат и приёмка |
|---|---|---|
| HH-01 — hh.ru read source | Текущий приоритет | Локальный токен, read-only preview, collector:test на отдельной таблице и проверка scheduled run. Зафиксировать coverage/ошибки без секретов; не считать mocks доказательством live-доступа |
| HH-02 — качество HH-выборки | После HH-01 | Оценить ролевые запросы и RU-условия найма; structured languages только с корректными evidence/scope; detail cache/watermark при измеренной необходимости, без пропуска изменений и ложного закрытия |
| LANG-01 — Language Intelligence v1 | Незавершённая локальная приёмка | Приёмка opt-in колонок в локальном n8n/Sheets; проверка выбранной модели на размеченных данных. Код и fixtures не заменяют эти проверки |
| LANG-02 — качество и discovery | После evidence LANG-01 | Расширение грамматик/benchmark; company/team signals только после проверки scope; измеренные tokens/cost, история source yield, sample size и exploration до адаптивного scheduler; UI корректировок, cross-process cache lock и pruning |
| CTX-01 — AI context engineering | Документация объединена в PR #17 | Измерить стоимость контекста на сопоставимых задачах без ухудшения качества |
| DOC-01 — резюме | После LANG-01, этап D | Автоматический текстовый PDF: извлекаемый текст, проверка layout и состава; адаптация/редактирование с provenance и подтверждением изменений. Отдельно проверить результат пользователем; не выдавать новые утверждения за факты |
| MATCH-01 / JR-009 | Поддержка C | Наблюдать подтверждённые пробелы новых выборок, согласовать quality gate. LLM оценивать только против baseline простых правил; не требовать повтор всей старой разметки |
| SRC-02 / JR-014 | По пробелам покрытия | Добавлять источники с официальным read API, fixtures, обработкой неполного feed и отчётом; semantic dedup — отдельное решение |
| COL-01 / JR-005,008 | Эксплуатационная проверка | Зафиксировать локальный multi-source writer evidence и повторяемость расписания; без содержимого CRM/credentials |
| DEV-01 / JR-001,003,007 | Поддержка разработки | Сохранять CI и совместимость; обязательные branch checks при доступности правил репозитория |
| DEV-02 / JR-004,006 | При изменении writer | Проверять insert/dedup/update, first/last_seen и ручные поля на отдельной таблице |
| JR-002 / часть DEV-01 | До инфраструктурного изменения или второго пользователя | Вернуть отложенные digest, изолированный backup/restore и upgrade/rollback; доказать восстановление без записи в рабочую Sheets |
| APP-01 | Завершить B до APP-02 | Проверить один разрешённый live upload/Submit/receipt, unknown/no-repeat; read-only DOM не считается отправкой |
| DATA-01 / часть JR-011 | До реальных отправок | Постоянное хранение package/approval/attempt, reservation, crash recovery и защита от повторов; выбор продуктовой БД оформить ADR |
| APP-02 | После B+C+D+DATA-01 | Один канал: подготовка → пользовательская проверка → отправка → подтверждение; ручной fallback |
| APP-03 | После APP-02 | Автоматизация выбранного списка: opt-in, дневной лимит, timezone, pause/recovery |
| APP-04 | После APP-03 и quality gate | Автоматический отбор по правилам с повторной проверкой ограничений |
| UX-01 / JR-012 | До пилота | Профиль, выдача, документы, очередь, история без обязательной ручной настройки JSON |
| SaaS-01 / JR-010,011,013 | До второго пользователя | Auth/isolation, hosting, private storage, lifecycle и проверяемое восстановление |
| JR-015 | По UX потребности | Уведомления с consent, timezone, dedup и отключением |
| BIZ-01 / JR-016 | После pilot evidence | Цена, billing и экономика на основе наблюдаемой ценности |

Не включать Kubernetes, микросервисы, массовый scraping или LLM scoring без проверяемой потребности. Старые JR-ID сохранены для трассировки. Выполненные шаги остаются в PR/roadmap; не добавляйте сюда повторные блоки истории релизов.
