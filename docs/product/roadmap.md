## Текущая итерация: C / MATCH-01

1. Реализовано: профиль ролей, seniority, страны и предпочтительного языка команды; обязательный remote отделён от пожеланий. Пользователь ещё может уточнить настройки.
2. Реализовано: объяснения совпадений, противоречий и неизвестных условий. Remote, страна найма и язык команды — разные признаки.
3. Реализовано: фиксированная выборка до 24 вакансий, включая основную, неясную и исключённую группы; отметки «подходит / не подходит / уточнить» с причиной. Первая разметка получена: 23 из 24.
4. Разобрано: optional hybrid, офисное условие роли, явные страны найма и недоступность описаний. Исправления закреплены регрессиями; v0.7.1 разделяет интерес/условия/доступность текста. Порог качества ещё не принят: raw disagreements не равны ошибкам.
5. Добавлять источники по обнаруженным пробелам покрытия, а не ради количества.

Цель этапа: понятный персональный список и проверенное качество. [Разбор первой выборки](../research/matching-review-2026-10-30.md) выполнен; следующий шаг — короткая проверка исправленной выдачи перед D. Повторная полная разметка не нужна.
Не вводить LLM scoring до оценки простых правил. Не скрывать автоматически все вакансии с неизвестной зарплатой или языком.

## Порядок после C

D — база фактов и генерация резюме. B необходимо довести до проверенного разрешённого сценария до E.
DATA-01 — продуктовая БД для версий пакетов, approval и попыток до реальной отправки.
E — один поддерживаемый канал с проверкой пользователем; F — автоматизация выбранного списка, затем отбора по правилам.
G — ограниченный пилот 3–5 кандидатов; это плановая когорта, не существующие пользователи.

## Сохранённые решения

- n8n остаётся локальным, облако не получает прямой доступ к localhost.
- Работающие collector, ID и ручные поля CRM сохраняются.
- Backup/restore и фиксация image digest отложены пользователем до изменения инфраструктуры/подключения второго пользователя; не блокируют текущую работу над matching.
- Auth и изоляция обязательны до второго пользователя; внутренняя БД n8n не является продуктовой БД.
- Календарные сроки не обещаны. Резюме и автоотклики входят в основной scope.
- [Порядок выпуска](../operations/releases.md): docs, проверки, конкретный commit, тег, Release, инструкция. Опубликованные теги не переносить.

## Уточнение приоритета: CI перед MATCH-01

По решению пользователя сначала усилены автоматические проверки: ESLint, JSON/config contracts и PR CI.
[Инструкция и ограничения](../operations/ci.md). Реальный n8n/Sheets остаётся локальной проверкой; обязательность checks через branch ruleset отдельно не настроена. Усиление CI выполнено, работа вернулась к MATCH-01.

## MATCH-01 iteration 1 — v0.7.0

Реализованы профиль/предпочтения, title seniority, отдельные language signals, объяснения priority/review/excluded и контрольная выборка до 24 с export/import оценок. Первый gate пройден: пользовательская разметка разобрана. В iteration 2 / v0.7.1 исправлены подтверждённые ошибки условий и UI. Этап C не закрыт автоматически по числу тестов; перед D проверить результат текущей доработки.

Branch ruleset проверен через GitHub API: текущий приватный репозиторий требует GitHub Pro для функции; privacy и тариф не менялись. CI работает; merge выполняем только после успешных checks.
