# План разработки и контрольные точки

> Обновление 29.10.2026: получены экспорт и точный JS. Актуальные подтверждения, ограничения и результаты 12 тестов — [аудит экспорта](../audit-workflow-export.md). Противоречащие ему утверждения ниже об отсутствии workflow/кода относятся к первоначальному срезу. Baseline gate ещё не закрыт.


## Итерация 0 — зафиксировать то, что работает

Результат этого пакета: аудит, структура, as-is, целевая модель, ADR и backlog. Далее локально JR-001–004. Пока они не завершены, не реализовывать новые функции и не обновлять инфраструктуру.

**Baseline gate:** экспорт совпадает с запущенным workflow; JS доступен; версия и volume известны; runtime config и Sheets headers зафиксированы; два прогона не создают дублей и сохраняют ручные данные; backup восстановлен изолированно; документированы известные ошибки. Чеклист отмечает владелец по доказательствам. Текущий статус — НЕ пройден.

## Итерация 1 — надёжный single-user

JR-005–009: ошибки, regression tests, закрепление версии, run summary, объяснимый подбор. Изменения отдельными малыми PR с сохранением baseline fixtures. По каждой новой логике — до/после на фиксированной выборке и rollback.

**Quality gate:** нет silent failure и ложного закрытия на error fixtures; rerun идемпотентен; manual fields сохранены; по выборке вакансий есть оценка пригодности и причины unknown. Порог качества выбирается по первой ручной разметке, не выдумывается заранее.

## Итерация 2 — доказать pilot scope

JR-010, проектирование JR-011–013. Уточнить: индивидуальные аккаунты или организации; общий каталог или приватные источники; нужные CRM этапы; каналы; частота; допустимая задержка; модель доступа к аккаунтам и deletion. До ответов не строить сложную tenant hierarchy.

**Pilot gate:** auth и isolation tests, source dedup, импорт с сверкой и rollback, удобный onboarding, последнее успешное обновление и состояние ошибок доступны; условия использования n8n и источников проверены для финального сценария; понятны support и обработка удаления данных.

## Итерация 3 — ограниченный пилот

3–5 пользователей как плановая когорта, не текущая база. Измерять activation (профиль → первая полезная вакансия), время до ценности, полезные/просмотренные вакансии, долю ложных совпадений, возвращения, причину отказа, стоимость сбора/подбора на активного пользователя. Отклик и интервью — запаздывающие метрики, не полностью контролируются сервисом.

## Решение о росте

Масштабировать при подтверждённой полезности и наблюдаемых ограничениях. Сначала измерить p95 длительности сборов, lag, API/Sheets errors, DB contention, расходы и поддержку. Цели доступности и нагрузки задать по нуждам пилота. Не назначать PostgreSQL/queue migration по произвольному числу пользователей.
