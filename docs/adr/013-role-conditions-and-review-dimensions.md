# ADR 013 — Условия конкретной позиции и раздельные оценки

Дата: 2026-10-30. Статус: Accepted. Уточняет ADR 011 и 012.

## Контекст

Первая пользовательская выборка содержит 23 оценки из 24. Найдены ошибки: optional hybrid трактовался как обязательный офис; общий remote-first маскировал офисный формат позиции; формулировка о рассмотрении кандидатов в конкретной стране не распознавалась. Общая оценка смешивала интерес к роли, условия найма и невозможность прочитать описание. [Разбор](../research/matching-review-2026-10-30.md).

## Решение

- Явное требование офиса для этой позиции имеет приоритет перед корпоративным remote-first и общими льготами. Офисная локация также не отменяется общими словами о компании. Противоречие между офисной локацией и явным remote для этой роли остаётся unknown.
- Optional hybrid не требует офиса. Отдельное обязательное посещение сохраняет силу, даже если рядом есть добровольный hybrid.
- Явное ограничение страны кандидатов имеет приоритет перед глобальной культурой компании. BG должна быть альтернативой в том же списке найма; офис или зарплатный пример в BG не является разрешением.
- Возможность работать за границей до 90 дней сама по себе не доказывает постоянный remote или найм из BG. Нераспознанное не превращается в подтверждённую доступность.
- Географические правила имеют отдельный идентификатор `remote-bg-v2` в `geography.policy`; новый snapshot перечисляет `geographyPolicies`. Порядок personal-match-v1 и fingerprint настроек не меняются. Старые записи без geography policy относятся к v1; старые snapshots не пересчитываются.
- Описание раскрыто по умолчанию. Общая оценка сохраняется; labels schemaVersion=2 дополнительно хранит необязательные `roleInterest`, `conditions`, `description`. Общая оценка может быть null для частичного черновика. Оценки v1 читаются без домысливания новых полей и без перекодирования причин.
- В браузере и CLI применяется один валидатор ответов. Импорт проверяет весь файл до изменения формы. Повторное открытие через `matching:report -- FILE --open` обновляет HTML и загружает оценки; исходные JSON и старое решение алгоритма сохраняются.

## Альтернативы и последствия

Не вводим LLM scoring или автоматическое переобозначение отказов по тексту комментария: первая выборка этого не обосновывает. Не считаем любое несовпадение ручной и машинной оценки доказанной ошибкой. Страновой парсер остаётся ограниченным набором правил, а remote — отдельным от права на работу признаком.

Runtime dependencies, сервисы и миграция CRM не нужны. Старый v0.7.0 reader не понимает новые labels v2: для них нужен v0.7.1 или новее. Существующие v1 labels и snapshots продолжают читаться новой версией. Рабочий writer, ID и ручные поля не меняются.

Пересмотр: новая размеченная ошибка, расширение страны профиля за BG либо переход к проверенному многоязычному извлечению условий. Расширение правил подтверждать положительными и отрицательными примерами.
