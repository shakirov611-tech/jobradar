# ADR 007 — Локальный scheduled writer и отчёты

Дата: 2026-10-29. Статус: Accepted for implementation; runtime verification pending.

## Контекст

v0.4 подтверждён пользователем на рабочей таблице. Sheets upsert читает существующие
ID перед записью и требует одного writer. Атомарная распределённая блокировка в
Sheets и n8n workflow static data отсутствует. n8n работает на Windows локально.
Пользователь хочет минимум ручных действий, расписание и видимый результат.

## Решение

Windows Task Scheduler каждые 3 часа запускает Node runner. Эксклюзивный файловый
lock в единственной рабочей папке сериализует вызовы. Runner создаёт временный n8n
webhook workflow с текущей логикой v0.4, запускает один раз, принимает счётчики и
сохраняет локальный отчёт. При успехе удаляет временный workflow. При неоднозначном
выполнении сохраняет lock и workflow, требует проверки до следующего сбора.
Ручной v0.4 сохраняется для возврата, но не должен работать параллельно.

Установщик сначала проверяет новый pipeline на синтетических данных в тестовой
таблице. Не меняем Docker/volume и не поднимаем облачный доступ к localhost.
Backup/restore остаётся отложенным по прямому решению пользователя.

## Альтернативы

- Только Schedule Trigger n8n: удобнее, но без надёжной блокировки writer не закрывает
  текущую задачу; static data check/set не является атомарным lock.
- Менять глобальную concurrency n8n: затрагивает прочие workflows и не решает
  конкуренцию с manual Execute, требует изменения инфраструктуры.
- PostgreSQL/Redis: подходят для нескольких writer/пользователей, избыточны сейчас.
- Долгоживущий Node-процесс: требует открытой консоли или отдельного service manager.

## Последствия

Работает только при включённом ПК и пользовательской сессии; нет внешних alerts.
Одна папка и один способ запуска обязательны. Не обещаем exactly-once или транзакцию
между Google Sheets и Node; при неоднозначности выбираем остановку и разбор.
Новые временные workflows дают небольшую нагрузку на локальный n8n; успешные executions
не являются постоянным журналом. Отчёты не содержат исходных вакансий и секретов.

## Пересмотр

При hosted pilot перейти к постоянному worker, продуктовой БД, уникальным ключам,
распределённым locks и мониторингу. До включения нескольких пользователей этот
локальный файловый lock не расширять на сетевые папки.
