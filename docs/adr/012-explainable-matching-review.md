# ADR 012 — Объяснимый подбор и локальная оценка

Дата: 2026-10-29. Статус: Accepted for implementation.

## Контекст

После remote view нужны персональные причины и измерение ошибок; данных для оценки точности ещё нет. Пользователь согласовал MATCH-01 после CI. Рабочая CRM должна сохранять историю.

## Решение

Дополнительный matching блок профиля с явной валидацией и fingerprint. Чистая функция выдаёт priority/review/excluded и reasons/gaps/unknowns/exclusions без числового fit score. Роль и remote/страна определяют противоречия; seniority и язык команды — мягкие предпочтения. Языковые требования отделены от языка команды; текст описания сам по себе не свидетельство.

Оценка на локальном сбалансированном snapshot до 24 вакансий, включая исключённые и другие роли. Offline HTML, localStorage с явным сообщением о доступности, переносимый JSON export/import. Ответы связаны с snapshotId, profile fingerprint и contentHash. CLI сравнивает с исходным снимком. Никаких секретов, LLM вызовов, БД или передачи оценок третьим лицам.

## Последствия

Мало новых зависимостей (нет runtime dependencies), сохранён writer. Снимки накапливаются локально; их нельзя удалять до разбора оценок. Балансировка не даёт market accuracy. Профиль не содержит базу подтверждённого опыта: полный fit пока невозможен. При изменении policy менять её идентификатор; старые результаты не пересчитывать без нового snapshot.
