# ADR 016 — hh.ru как ограниченный поисковый источник

Статус: Accepted for implementation. Дата: 2026-11-05.

## Контекст

Ленты компаний Greenhouse/Lever ограничивают покрытие. hh.ru предоставляет поисковую выдачу: это меняющаяся выборка, а короткая карточка не заменяет полное описание для language analysis. Коллектор уже имеет единый writer и разделение discovery/enrichment/personalization.

## Решение

Добавить один opt-in источник `hh/search` в текущий registry. Поисковые запросы и бюджеты — конфигурация; пользовательские языки не становятся глобальным фильтром API. Несколько запросов объединяются по native ID, страницы и details обходятся с чередованием запросов. `hh_search_<id>` стабилен при смене query/employer. Общие вакансии проходят прежний language/matching pipeline, ролевые строки — прежний n8n writer.

Использовать авторизованные GET на фиксированном `api.hh.ru`; local env хранит token и contact header. Не выполнять OAuth refresh, scraping, CAPTCHA bypass или отправку откликов. Общий bounded GET helper сохраняет прежнюю retry policy ATS; HH имеет свой pacing/deadline. Загрузить полный detail до нормализации. Отсутствие/архивирование detail не закрывает CRM-запись.

Разделить `status` успешной операции и `coverage` поискового окна. Достижение объявленного бюджета — успешный ограниченный сбор с `complete=false`, а не заявка на полный рынок. Ошибка API/schema прерывает HH, но не остальные источники. CRM schema, manual fields, first_seen/last_seen семантика не меняются.

## Альтернативы и причины отказа

- Отдельный n8n workflow для HH дублировал бы writer, правила и управление credentials.
- Источник на каждый query давал бы несколько ключей одной вакансии и усложнял дедупликацию.
- Полное сканирование без бюджета увеличивало бы стоимость и риск throttling, не обеспечивая snapshot consistency.
- Нормализация search snippets теряла бы существенные языковые и географические условия.
- Detail cache/watermark пока не вводятся: у search нет проверенной здесь гарантии обнаружения всех изменений. Существующий content cache уже сокращает повторный AI-анализ.

## Ограничения и пересмотр

Это MVP одного набора поисковых запросов, без полноты рынка или semantic dedup между ATS. Многоязычный scope вакансии не выводится из сайта, города или языка клиента. Live-доступ зависит от разрешений HH-приложения и локальной настройки. Пересмотреть при измеренном исчерпании бюджета, изменении API/условий, необходимости повторной проверки старых вакансий или multi-user discovery с объединением запросов. Поля, лимиты и официальные источники поддерживаются в [справочнике адаптера](../research/source-coverage-v0.6.md#hhru-search-и-details).
