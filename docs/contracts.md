# Контракты и границы изменений

Проверено по коду `be5dafe`, 2026-11-03. Это реализованные границы, а не список желаемых гарантий. Поля и целевая схема — в [data-model](data-model.md); пути и тесты — в [карте](architecture/codebase-map.md).

## Sources → collector / preview

`normalizeFeed(source, feed, observedAt, profile)` возвращает rows, catalog, total. Rows содержат ролевые вакансии для CRM; catalog также содержит сигналы обзора. Remote/geography и персональные оценки не должны неявно изменять writer payload.

ID scoped по provider/board/region и external ID; существующий ключ Airbnb сохраняется. Некорректный feed, запись, ID или дубль в multi-source feed отклоняет **весь источник**, не отдельную запись в quarantine. collectSources изолирует ошибку источника и отдаёт явный failed. Успешный пустой массив допустим. HH search может повторять ID между запросами/страницами: адаптер объединяет их до загрузки details и нормализации. Scope `hh_search_<id>` не зависит от employer или поискового текста. `coverage` в source summary описывает окно/лимиты отдельно от транспортного `status`; это не дополнительная колонка CRM. Недоступные/архивные HH details пропускаются без закрытия существующих записей. Details pagination/retry — в [справочнике](research/source-coverage-v0.6.md#справочник-существующих-адаптеров).

`validateEnvelope` в multi-collector проверяет run ID, уникальность строк/источников, принадлежность строк успешному источнику, счётчики, дату наблюдения и whitelist колонок. Это не полная проверка каждого поля внешнего API: URL может остаться пустым, source timestamps не имеют универсальной строгой валидации.

## Collector → storage

`prepareVacancyUpsert(incoming, existing)` требует уникальные входные и существующие vacancy_id и корректный last_seen_at. Insert задаёт first_seen_at = last_seen_at. При update first_seen_at отсутствует в payload, включая случай пустого исторического значения; дата задним числом не выдумывается.

Нормализация/whitelist исключает ручные поля, Sheets appendOrUpdate сопоставляет по vacancy_id. Сам prepareVacancyUpsert копирует входные поля и не является универсальным фильтром от произвольного payload. При изменении writer проверяйте всю цепочку и тест сохранения ручных полей.

**Не реализовано:** сравнение last_seen_at с сохранённой датой для защиты от старого события, транзакция Sheets, автоматическое закрытие исчезнувшей вакансии. Runner lock действует только внутри одного рабочего каталога; не гарантирует отсутствие внешнего writer.

## Lifecycle и результаты

Временный workflow создаётся/активируется/вызывается, результат сверяется с run ID и counts; cleanup деактивирует и удаляет. Повтор регистрации разрешён только для распознанного ответа «собственный webhook ещё не зарегистрирован»; generic 404 и неоднозначный результат записи не переигрываются. Cleanup ограниченно повторяет 409.

При частичном отказе sources успешные строки могут быть записаны, общий результат partial не считается полностью успешным. При отказе всех источников запись не выполняется. Не объявляйте run успешным по одному HTTP 200 без проверки completion. Unknown требует проверки состояния, а не снятия lock и повторного POST вслепую.

## Review / resume / applications

Оценки подбора связаны с snapshot; перенос старого формата сохраняет его смысл. Изменение snapshot/profile требует новой версии, а не переписывания исторических оценок.

Пакет резюме связан с profile/vacancy/package hash. Состав допускает только разрешённые статусы фактов; изменение или восстановление выбора снимает approval экспорта. Автоматическая отправка из этого approval не следует. Подробности — [ADR 014](adr/014-local-facts-resume-review.md).

Submitted в application spike требует подтверждения соответствующего пакета/вакансии. Неоднозначный результат — submission_unknown без автоматического повтора. Это fixture-контракт, не доказательство live-отправки или durable storage.

При расширении контракта добавляйте проверку потребителей и совместимости. Target-инварианты многопользовательской БД не выдавайте за гарантии текущей Sheets.


## Language Intelligence v1

Общий `language_analysis` отделён от `matching.language_fit`; профиль не влияет на набор полученных вакансий или shared cache. Ошибка AI сохраняет запись и явный failed/pending статус. Старое поле `language` не переопределяется. При `JR_LANGUAGE_SHEETS=1` whitelist допускает два JSON-поля `language_analysis` и `language_fit`; второе включает fingerprint владельца локальной проекции. Только эти новые машинные поля обновляются, auto-map и vacancy_id сохраняются. Read-back сверяет фактически записанные значения. Точная [схема, инвалидация и rollout](operations/language-intelligence.md), [ADR 015](adr/015-language-intelligence.md).
