# v0.7.1 — Условия вакансии и понятная разметка

## Изменения

- Optional hybrid больше не означает обязательный офис. Офисное условие конкретной позиции имеет приоритет перед общим remote-first.
- Учитываются явные страны рассмотрения кандидатов. Корпоративная глобальная культура и офис в BG не отменяют ограничение страны найма.
- Временная работа за границей не подтверждает постоянный remote.
- Описание в контрольной выборке раскрыто сразу. Отдельно можно оценить интерес к роли, условия и доступность описания; частичный черновик сохраняется.
- Новая версия читает исходные labels v1. Общие оценки не переинтерпретируются. Новые файлы имеют schemaVersion=2.
- Обновлены ADR, модель данных, roadmap/backlog и разбор первой пользовательской выборки.

## Обновление

Замените файлы проекта в прежней папке, сохранив `.env.integration`, `.collector-state` и свои настройки. Для новой выдачи:

```powershell
npm.cmd run collector:preview -- --open
```

Повторять все оценки не нужно. При необходимости открыть прежнюю выборку с загруженными оценками и новым интерфейсом:

```powershell
npm.cmd run matching:report -- "C:\путь\jobradar-labels-XXXXXXXXXXXX.json" --open
```

Для второй команды соответствующий исходный `review-<snapshotId>.json` должен оставаться в `.collector-state`. Пересоздаётся HTML; исходные JSON и прежние решения алгоритма не меняются. Новый сбор использует исправленные правила. Обновление n8n, Docker и расписания не требуется.

## Проверки и ограничения

Регрессионные, контрактные и browser fixtures выполняются через существующий CI. Перед выпуском требуются успешные checks точного commit PR. Рабочая Google Sheets не используется тестами.

CRM payload, vacancy_id и ручные поля сохранены. Локальный n8n в этой доработке из облака не запускался. Исправление эвристик не подтверждает найм из BG, право на работу или полное соответствие кандидата. Разметка первой выборки разобрана, но точность на всём рынке не установлена.
